## 롯데 프로젝트 - Perplexity Search SDK 검토 결정

- 오딘이 Perplexity Search SDK 문서(`https://docs.perplexity.ai/docs/search-sdk/overview`)를 공유하며 롯데프로젝트에 참고할 만한 툴인지 검토를 요청했다.
- 1차 판단: 참고 가치는 있으나 롯데 핵심 정제 파이프라인에 바로 도입하지 않는다.
- 적합한 용도: 공개 웹 근거 수집 보조, 시장/경쟁/상품 공개 근거 후보 수집, 고객 Q&A 준비.
- 부적합한 용도: 롯데/마켓링크 실데이터 외부 전송, SKU 속성 자동 확정, confidence score 직접 근거화.
- 결정: 참고 자료로 기록하고, 롯데 프로젝트 시작 단계에서 `public evidence adapter PoC` 후보로 재검토한다.
- 재검토 조건: synthetic/public SKU 5~30개, read-only, 비식별 키워드만 사용, 결과는 `candidate evidence` 및 `needs_human_review=Y`로 처리, 실제 데이터/API 비용/외부 전송은 오딘 승인 및 소라 게이트 후 진행.

## Practical Loop Engineering 학습 및 팀 공유

- 오딘이 Google 공유 링크(`https://share.google/dJDmTTHt3U3vidhrE`)를 공유하며 팀 학습과 공유를 지시했다. 실제 원문은 Addy Osmani의 `Practical Loop Engineering`(`https://addyo.substack.com/p/practical-loop-engineering`)으로 확인했다.
- 핵심 학습: 루프는 에이전트를 오래 돌리는 기능이 아니라 목표, 중단조건, 검증, 상태기록, 휴먼게이트를 함께 설계하는 운영 방식이다.
- 개발담당 준호에게 특별 강조: `goal`, `stop_when`, `abort_when`, `verifier`, `evidence`를 개발 작업카드에 포함하고, 같은 오류 3회 반복 시 중단/보고한다.
- 롯데 프로젝트 적용: 자동 정제 루프가 아니라 `작업자 → 테스트/검증 → 독립 검수 → 승인/기록` 구조로 흡수한다. 실데이터, 외부 API, 비용, 고객사 계정, 외부 발송은 승인 전 금지.

## Loop Engineering vs Graph Engineering 비교 HTML

- 오딘이 Google 공유 링크(`https://share.google/AFovwQNlrCZkCgDHB`)를 공유하며 앞의 Practical Loop Engineering 글과 비교해 루프와 그래프의 공통점/차이점을 HTML로 만들어 이 세션에서 볼 수 있게 하라고 지시했다.
- 실제 새 원문은 GeekNews/Hacker News Korea의 `Graph 엔지니어링 vs Loop 엔지니어링: 실제로 달라진 것은 무엇인가`(`https://news.hada.io/topic?id=32544`)로 확인했다.
- 핵심 결론: Loop는 하나의 목표를 반복 수행/검증하는 실행 단위이고, Graph는 여러 Loop와 작업 단계, 병렬 branch, handoff, shared state, veto, 비용/종료 조건을 연결하는 오케스트레이션 계층이다.
- 롯데 적용 판단: 준호는 Loop를 개발 실행 단위로 쓰고, 민호는 Graph를 팀 운영 지도와 승인/검증 흐름으로 관리한다. 작은 Confidence/HITL Loop부터 검증한 뒤 필요할 때 Graph로 확장한다.
